Requisitos del entorno

  • XAMPP (o equivalente) con PHP 8.2 y MySQL 8.
  • Node.js 20+ y npm.
  • Composer 2.x.
  • Navegador actualizado (Chrome, Edge o Firefox).

SMTP (MAIL_*) para recuperación de contraseña. reCAPTCHA en producción: claves en backend y NEXT_PUBLIC_RECAPTCHA_SITE_KEY en el frontend.

Instalación y ejecución

Asume carpetas quorum-backend y quorum-frontend bajo quorum-codigo/ (paquete completo). Hay dos caminos para la base de datos; no los mezcles.

Camino A (oficial): dump SQL

  1. Inicia MySQL.
  2. Crea la base vacía quorum.
  3. Importa Base de datos/quorum.sql (phpMyAdmin o cliente MySQL).
  4. No ejecutes php artisan migrate --seed después del dump.

El dump trae usuarios con 2FA ya verificado. En local, pon TOTP_BYPASS_LOCAL=true y RECAPTCHA_BYPASS_LOCAL=true en el .env del backend, y NEXT_PUBLIC_RECAPTCHA_BYPASS_LOCAL=true en el .env.local del frontend. Nunca en producción.

Backend (ambos caminos)

cd quorum-codigo/quorum-backend
copy .env.example .env
composer install
php artisan key:generate
php artisan serve

Camino B (sin dump): tras key:generate, ejecuta php artisan migrate --seed y luego php artisan serve. Obtendrás catálogos + 5 usuarios de prueba, sin las fichas extra del dump.

API habitual: http://localhost:8000

GET http://localhost:8000/api/ping

Respuesta esperada: status: ok.

Plantilla Excel CPIC

El paquete ya incluye quorum-backend/storage/app/plantilla_asistencia.xlsx. Sin ese archivo, GET /api/reportes/excel/{ficha} falla.

Frontend

cd quorum-codigo/quorum-frontend
npm install
copy .env.example .env.local
npm run dev

La URL base de la API está en quorum-frontend/services/api.ts (por defecto http://localhost:8000). No uses NEXT_PUBLIC_API_URL en docs nuevas: ya no figura en .env.example del frontend.

Orden de arranque

  1. MySQL
  2. php artisan serve
  3. npm run dev

Variables de entorno

Backend (quorum-backend/.env)

Variable Notas
APP_URL URL de la API (p. ej. http://localhost:8000).
FRONTEND_URL URL del SPA Next (sin barra final).
SESSION_DOMAIN p. ej. localhost.
SANCTUM_STATEFUL_DOMAINS localhost:3000, localhost:3001, etc.
DB_* Conexión MySQL.
MAIL_* SMTP para recuperación de contraseña.
RECAPTCHA_SITE_KEY, RECAPTCHA_SECRET_KEY Google reCAPTCHA v3.
RECAPTCHA_BYPASS_LOCAL true solo con APP_ENV=local: omite HTTP a Google.
TOTP_BYPASS_LOCAL true solo local: omite 2FA en login y API protegida.

Frontend (quorum-frontend/.env.local)

Variable Notas
NEXT_PUBLIC_RECAPTCHA_SITE_KEY Clave pública v3 (producción).
NEXT_PUBLIC_RECAPTCHA_BYPASS_LOCAL true: no carga script Google; envía local-bypass.

Para desarrollo sin reCAPTCHA ni 2FA: en backend RECAPTCHA_BYPASS_LOCAL=true y TOTP_BYPASS_LOCAL=true; en front NEXT_PUBLIC_RECAPTCHA_BYPASS_LOCAL=true. Nunca en producción.

Desarrollo local

DevQuickLogin

En npm run dev (NODE_ENV=development), la pantalla /login muestra el panel «Acceso rápido de pruebas» que rellena correo y contraseña (no inicia sesión solo). Implementado en components/auth/DevQuickLogin.tsx.

Login unificado

  • POST /api/auth/login — correo, contraseña, recaptcha_token.
  • POST /api/auth/login-aprendiz — 410 Gone; mensaje: usar login principal. Endpoint legacy.
  • Aprendiz: sin 2FA; redirección UI a /mi-historial.
  • Staff: totp_sesion_completa: false hasta verificar TOTP (salvo bypass).

Autenticación y sesión

  • Laravel Sanctum SPA: cookies stateful entre Next y API.
  • Middleware EnsureTotpSessionOk en la mayoría de rutas de panel (staff con 2FA completado en sesión).
  • Excepciones sin TOTP en sesión: GET /api/mi-historial, PATCH /api/perfil/contrasena (con auth:sanctum).
  • Recuperación: POST /api/auth/recuperar, POST /api/auth/reset (throttle 5/min).

API REST (resumen)

Prefijo /api — ver quorum-backend/routes/api.php.

  • Health: GET /ping
  • Auth público: POST /auth/login; POST /auth/login-aprendiz (410); POST /auth/recuperar, POST /auth/reset
  • Auth sesión: POST /auth/logout, GET /auth/me, POST /auth/2fa/configurar, POST /auth/2fa/verificar
  • Aprendiz: GET /mi-historial
  • Perfil: PATCH /perfil/contrasena
  • Con Sanctum + TOTP OK: dashboard, usuarios, macrorregiones, regionales, centros/programas (lectura), fichas CRUD + aprendices + import, asistencia (historial, evidencias, iniciar/guardar/actualizar, excusa-evidencia), reportes excel, coordinador/*, calendario, configuración, festivos, historial-actividad
  • Admin (middleware admin): /admin/centros-formacion*, /admin/programas-formacion*, /admin/auditoria-asistencia

Troubleshooting técnico

  • CORS / cookies / 401: alinea FRONTEND_URL, SESSION_DOMAIN, SANCTUM_STATEFUL_DOMAINS con el puerto real del navegador (3000 o 3001).
  • API caída: MySQL, php artisan serve, firewall.
  • Excel 500: falta plantilla_asistencia.xlsx en storage.
  • reCAPTCHA 422: claves válidas o bypass local en ambos lados.
  • Staff bloqueado en API: completar 2FA o TOTP_BYPASS_LOCAL=true en local.
  • 410 login-aprendiz: cliente antiguo; migrar a POST /auth/login.
  • Aprendiz no entra tras seed: asignar contraseña en BD o desde admin usuarios.
